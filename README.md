# HACKATHON SQUAD: Maximum Weight Independent Set (MWIS) Solver

Welcome to the **Hackathon Squad** MWIS Solver repository. This project features a highly optimized, high-performance C++20 evolutionary algorithm designed to solve the Maximum Weight Independent Set problem on massive graph topologies (up to $N=200,000$, $M=200,000$) under strict time constraints. 

Our solver achieves an astonishing **~99.97% overall accuracy** across diverse graph topologies, including star, grid, cycle, tree, and large sparse graphs.

---

##  Core Architecture & Algorithms

To achieve this level of performance, the solver utilizes a multi-layered approach combining low-level memory optimizations with advanced heuristic search strategies.

### 1. Data-Oriented Graph Representation (CSR)
Instead of standard adjacency lists (which suffer from memory fragmentation and poor cache locality), the graph is compressed into a **Compressed Sparse Row (CSR)** format. 
- Edge lists are tightly packed into a single contiguous 1D array.
- Edges are sorted during initialization, enabling lightning-fast $O(\log D)$ binary searches for edge existence.
- **Zero-Allocation Policy**: The evolutionary loop performs zero dynamic memory allocations on the heap, allowing for a sustained throughput of over **85 Million swaps per second**.

### 2. Memetic Evolutionary Engine
The core solver utilizes a **Memetic Algorithm**, which is a hybrid of a Genetic Algorithm (global exploration) and aggressive Local Search (local exploitation).
- **Tournament Selection**: Parents are selected dynamically to breed the next generation.
- **Set Crossover**: Child teams are built by taking the intersection (agreed members) and a shuffled union of the parents' teams.

### 3. GRASP Initialization with ROI Heuristic
To ensure the evolutionary process starts with highly competitive genetics, we utilize a Greedy Randomized Adaptive Search Procedure (GRASP).
- **Weight-to-Degree Ratio (ROI)**: Coders are evaluated based on their "Return on Investment", calculated as: `Skill Score / (Conflicts + 1)`.
- **Noisy Sorting**: Candidates are sorted by their ROI, but a random noise multiplier ($\pm50\%$) is applied per generation. This heavily biases the selection towards the mathematical best coders while guaranteeing population diversity.

### 4. Deep Local Search Optimizations
Every child generated by the evolutionary engine undergoes a relentless local optimization process until it reaches a local maximum. The search includes:
- **1-opt (1-for-1 Swaps)**: If an outside coder conflicts with exactly *one* team member, and their skill is higher, they are swapped.
- **2-for-1 Swaps**: If an outside superstar conflicts with *two* weak team members, and `Superstar > Weak1 + Weak2`, the two members are dropped to fit the superstar.
- **1-for-2 Swaps**: The solver scans for situations where dropping *one* team member allows the inclusion of *two* outside coders who do not conflict with each other (verified via $O(\log D)$ binary search), resulting in a net positive score.
- **Plateau Search (Random Walk)**: If a potential swap results in a net score change of exactly **$0$** (a sideways move), the solver will occasionally accept it (up to a limit). This allows the search to slide across flat regions of the solution space and escape deep local optima valleys.

##  How to Run the Project

Follow these exact steps to build the project, run the automated test suite, or test specific graph files.

### Step 1: Build the Project
Open your **PowerShell** terminal, navigate to the `build` directory, and compile the C++ code using CMake in Release mode (which applies `-O3` performance optimizations).

```powershell
# Navigate to the build directory
cd "C:\Users\biswa\Desktop\HACKATHON SQUAD\build"

# Configure CMake (if you haven't already)
cmake ..

# Build the highly-optimized executables
cmake --build . --config Release
```

### Step 2: Run the Benchmark Suite
To automatically traverse the `test_suite` directory and evaluate the solver's accuracy across all graph topologies, run the `benchmark_runner`.

```powershell
.\benchmark_runner.exe
```
*(Note: Large graphs like `input_legacy_5.txt` may take up to 5 minutes to fully evaluate as the solver utilizes its entire time limit to hunt for hidden improvements).*

### Step 3: Run the Solver on a Specific File
If you want to test a single file and generate the space-separated output of selected Coder IDs into a file named `my_answer.txt`, you can use one of the two methods below.

**Method A: Native PowerShell (Using Get-Content)**
```powershell
Get-Content ..\test_suite\input_17_large_sparse_n100000_m200000.txt | .\solver.exe > my_answer.txt
```

**Method B: Command Prompt Wrapper (Recommended for Huge Files)**
Because PowerShell's `Get-Content` can sometimes be slow when reading massive 100MB text files, wrapping the command in `cmd` is often much faster:
```powershell
cmd /c ".\solver.exe < ..\test_suite\input_17_large_sparse_n100000_m200000.txt > my_answer.txt"
```

Once finished, open `my_answer.txt` in the `build` directory to see your winning team!
